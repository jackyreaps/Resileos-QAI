# Olympus Agency

## 1. System name

**Olympus Agency** (short: **Olympus**).

| Layer | Name | Role |
|-------|------|------|
| Store / residual law | **Titanos** | Exact memory, gates, capacity |
| Agency system | **Olympus** | Named operator children (kin) |
| Residual specialist | **Zeus** | Structured answers; may decline |
| Growth order | Growth spine (RES-331) | Capacity → hub → mouth → optional surface |

Olympus does **not** rename Titanos. It names the **agency graph** of operators that develop, check, and reorganize under the capacity contract. Truth remains residual; kin never rewrite the ledger as a side effect of persona weight or context indexing.

## 2. Doctrine

1. **One ledger.** Titanos holds facts. Kin may propose eats, policy, hierarchical context probes, or mouth-prior patches; only `learn` / ingest writes durable triples.
2. **Named verbs.** Each child has one primary verb (answer, observe, organize, navigate-context, eat, excise, personify-metrics).
3. **Decline is legal.** Like Zeus, any kin may return `None` / no-op when out of scope.
4. **Frames top-down.** Finished frame envelopes constrain which personas and metric weights are admissible — not the reverse.
5. **Game structure.** Agency weights and enable bits are a **finite game** over probes (M1–M5, accept rates, context-hit utility), not open-ended self-reward on fluency.
6. **Context is not truth.** Hierarchical meaning indexes (Hermes) accelerate retrieval and layer navigation; they do not become a second fact store.

## 3. Core kin (ship-order)

| Kin | Verb | Surface | Writes residual? |
|-----|------|---------|------------------|
| **Zeus** | Answer / decline | `ask` / chain | No |
| **Iris** | Observe | Metrics, flags | No |
| **Metis** | Organize | Agency weights, policy table | No (config only) |
| **Hermes** | Navigate / layer context | Hierarchical meaning groups over stream, hub, or mouth context; sparse probe into Titanos | No |
| **Demeter** | Eat | Ingest → learn proposals | Only via controlled learn |
| **Asclepius** | Excise | Sparse mouth-prior / mask patch (gated) | No |
| **Mnemosyne** | Personify-metrics | Persona prompt packs + weighted M* under persona | No |

Optional later labels: **Hephaestus** (structure edit tooling), **Apollo** (eval / probe runner).

## 4. Relation to frames, LSA-class ideas, and persona growth

| Source | When finished / available | Effect on Olympus |
|--------|---------------------------|-------------------|
| Frame atlas / dimensionality | Catalog stable | Admissible axes for persona envelopes; no ideology scoring in store |
| Hierarchical sparse context (e.g. LSA-style meaning groups) | External research / optional kernels | Inspires **Hermes** contract only — hierarchical group-first probe, not a claim that LSA is shipped in-repo |
| Growth spine | Active | Mnemosyne, Asclepius, and heavy Hermes stay **after** hub durability + M1–M2 green |

**Archetypal persona development** = successive **envelopes** (allowed tools, metric weights, hub namespaces, context-layer depth). Evolution of the system = Iris→Metis loops + Hermes sparse probes + Demeter eats + optional Asclepius on the **prior**, under probes.

## 5. Game-theoretic branches (finite)

| Branch | Moves | Equilibrium sense |
|--------|-------|-------------------|
| **Honesty game** | Zeus answer vs decline; Mnemosyne tool-first | Invent rate → 0 |
| **Agency weight game** | Metis reweights children from Iris | Low-accept children down-weighted |
| **Context layering game** | Hermes hierarchical probe vs full scan | High hit utility, low wasted FLOPs; never invents missing rows |
| **Eat game** | Demeter propose learn vs reject | Only validated residue enters store |
| **Excision game** | Asclepius patch vs rollback | Probe must not regress M1–M2 |
| **Persona envelope game** | Mnemosyne weight vector under frame | Heavy weight on honesty metrics under persona |

No branch authorizes unbounded self-modification of Titanos parameters as “winning.”

## 6. Non-goals

- Kin as a second Oracle  
- Treating hierarchical context indexes as durable fact storage  
- Shipping third-party sparse-attention kernels as a product dependency before capacity + strict M4  
- Frame schools as runtime fact relations

# Growth Spine

## 1. Order (hard)

```text
1. Frame capacity + Oracle spine     (gate, tools, C0–C8, metrics M1–M8)
2. Hub namespace + durable learn       (user:/world:, restart-safe)
3. Text mouth under router           (tool-bound; invent rate → 0)
4. Later: adapt/train on hub state   (carrier / small mouth)
5. Optional later: personified UX    (only if product needs it — not required)
```

Personality and character are **top-down from frame capacity**, not from an
external video stack. Training on hub state is **later**. No third-party CVI
bridge is required to grow the spine.

## 2. What grows

| Now | Later |
|-----|--------|
| Residual triples + hub basins | Hub-conditioned mouth/carrier |
| Tool adherence and abstain honesty | Optional persona *prompt* within envelope |
| Declared φ/HF bounds | Only after M1–M4 green |

Growth ≠ larger decoder or longer context alone.

## 3. Metrics to instrument immediately

See capacity-contract §4 (M1–M8). Minimum dashboard:

1. tool adherence on fact turns  
2. invent rate after empty/abstain  
3. store + hub probe hit rate  
4. hub retain after load  

## 4. Checklist before “train personality” experiments

- [ ] Capacity wired (`HF_CAP = 64*k`)  
- [ ] Bulk path uses `learn_many`  
- [ ] Hub namespace stable across restart  
- [ ] Router classes on text path  
- [ ] M1–M3 measured on a small probe set  
- [ ] Scale admit policy documented  

## 5. Non-goals this phase

- Personified video as a dependency  
- Treating any system prompt as the fact ledger  
- Growing by surface polish without M1–M2
